Module 1 · 14 minTool calling · boucle · frameworks

Un agent, c'est un LLM qui appelle des outils dans une boucle.

Le modèle n'exécute jamais rien. Il émet une demande d'appel structurée (nom de l'outil + arguments JSON). Votre code l'exécute, renvoie le résultat dans la conversation, et rappelle le modèle. On répète jusqu'à ce qu'il réponde sans demander d'outil.

Le tool calling en 4 temps

  1. Déclarer les outils : un nom, une description (c'est elle que le modèle lit pour décider), un JSON Schema des paramètres.
  2. Le modèle choisit : il répond avec un bloc tool_use (Anthropic) ou tool_calls (OpenAI) et s'arrête avec stop_reason = "tool_use".
  3. Vous exécutez et renvoyez un tool_result lié à l'id de l'appel. En cas d'erreur, renvoyez le message d'erreur avec is_error : le modèle sait souvent corriger ses arguments.
  4. Le modèle reprend avec le résultat dans son contexte : nouvel appel, ou réponse finale.
▶Déroulez une boucle agentique
La boucle « à la main » · SDK Anthropic (Python) 
import anthropic, json
client = anthropic.Anthropic()

tools = [{
    "name": "get_weather",
    "description": "Météo actuelle d'une ville.",
    "input_schema": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"]},
}]

def run_tool(name, args):
    if name == "get_weather":
        return {"temp_c": 14, "pluie_mm": 3}
    raise ValueError(name)

messages = [{"role": "user",
             "content": "Parapluie à Lyon ?"}]

for step in range(10):  # jamais de while True
    resp = client.messages.create(
        model="claude-sonnet-5-5",
        max_tokens=1024,
        tools=tools, messages=messages)
    messages.append({"role": "assistant",
                     "content": resp.content})
    if resp.stop_reason != "tool_use":
        break                 # réponse finale
    results = []
    for block in resp.content:
        if block.type == "tool_use":
            try:
                out = json.dumps(run_tool(block.name, block.input))
                err = False
            except Exception as e:
                out, err = str(e), True
            results.append({
                "type": "tool_result",
                "tool_use_id": block.id,
                "content": out, "is_error": err})
    messages.append({"role": "user", "content": results})

print(resp.content[-1].text)

Workflow ou agent ?

Un workflow suit un chemin écrit d'avance dans le code ; un agent décide lui-même de ses étapes. Commencez toujours par le plus simple qui marche. Les cinq patterns de Building effective agents (Anthropic, 2024) :

Prompt chainingÉtapes en série, avec des contrôles entre elles.
RoutingUn classifieur envoie vers le bon prompt ou le bon modèle.
ParallélisationSections indépendantes en parallèle, ou vote sur plusieurs réponses.
Orchestrator-workersUn LLM découpe la tâche et délègue à des sous-agents.
Evaluator-optimizerUn LLM produit, un autre critique, on boucle.

Le pattern ReAct (raisonner, agir, observer, recommencer) est l'ancêtre de la boucle ci-dessus. Les modèles actuels le font nativement via le tool calling.

Les quatre frameworks

LGLangGraphGraphe d'états, persistance

Modèle mental : nœuds (fonctions), arêtes conditionnelles, état typé partagé.

Forces : checkpointing et reprise, human-in-the-loop avec interrupt, contrôle fin du flux, multi-agents.

Quand : workflows longs et explicites qui doivent survivre à un crash.

PyPydanticAIAgents typés, sorties validées

Modèle mental : un agent « à la FastAPI », sorties validées par Pydantic, injection de dépendances.

Forces : typage de bout en bout, multi-fournisseurs, tests faciles, traces OTel via Logfire.

Quand : équipes Python qui veulent des sorties structurées fiables.

OAOpenAI Agents SDKHandoffs et guardrails

Modèle mental : des agents qui se passent la main (handoffs), encadrés par des guardrails.

Forces : API minimale, tracing intégré, sessions, fonctionne aussi avec d'autres modèles.

Quand : multi-agents simples avec délégation, prototypes rapides.

CAClaude Agent SDKLe harnais de Claude Code

Modèle mental : Claude Code sous forme de bibliothèque, avec outils fichiers, bash et web intégrés.

Forces : sous-agents, hooks, permissions, MCP, Skills, compaction du contexte.

Quand : agents qui travaillent sur un système de fichiers ou du code.

!Pièges classiques
  • Trop d'outils : au-delà de quelques dizaines, le choix se dégrade. Regroupez, ou chargez les outils à la demande.
  • Descriptions vagues : la description est un prompt. Dites quand utiliser l'outil, quand ne pas l'utiliser, et le format attendu.
  • Pas de garde-fous : limitez itérations, tokens et coût. Confirmation humaine pour les actions irréversibles.
  • Contexte qui gonfle : chaque résultat d'outil s'accumule. Tronquez, résumez, ou déléguez à un sous-agent dont seul le résumé revient.
  • Prompt injection : ce que renvoie un outil (page web, mail) peut contenir des instructions. C'est une donnée, jamais un ordre.

Module 2 · 8 minModel Context Protocol · Agent Skills

MCP branche les outils. Les Skills apportent le savoir-faire.

MCP est un protocole ouvert (Anthropic, nov. 2024, adopté depuis par OpenAI, Google, Microsoft…) qui standardise la connexion entre une application LLM et des outils ou des données. On écrit un serveur une fois, tous les clients compatibles peuvent l'utiliser : c'est l'« USB-C des agents ».

À savoir réciter

RôlesL'hôte est l'application ; il crée un client par serveur.
Côté serveurTools : actions, choisies par le modèle. Resources : données en lecture, choisies par l'application. Prompts : gabarits, choisis par l'utilisateur.
Côté clientSampling : le serveur demande une complétion au LLM de l'hôte. Roots : périmètre de fichiers. Elicitation : le serveur demande une info à l'utilisateur.
TransportJSON-RPC 2.0 via stdio (local) ou Streamable HTTP (distant, a remplacé HTTP+SSE en 2025).
Cycle de vieinitialize (négociation des capacités) → tools/list → tools/call.

Agent Skills

Une Skill est un dossier avec un SKILL.md (frontmatter YAML name + description, puis des instructions), et éventuellement des scripts, gabarits ou docs. Né chez Anthropic, le format est devenu un standard ouvert fin 2025, lu aussi par Codex, Cursor, Copilot…

Le principe clé : la divulgation progressive. Au démarrage, l'agent ne voit que nom et description, quelques dizaines de tokens par Skill. Il charge le corps quand la tâche s'y prête, puis les fichiers annexes seulement si besoin. On peut donc en installer des centaines sans saturer le contexte.

release-notes/SKILL.md 
---
name: release-notes
description: Rédige les notes de version
  à partir des commits. À utiliser quand
  on demande un changelog.
---
# Notes de version
1. Lancer scripts/collect_commits.sh <tag>
2. Grouper : feat, fix, perf. Ignorer chore.
3. Remplir templates/notes.md

MCP ou Skill ?

QuestionMCP : à quoi l'agent peut-il accéder ?
Skill : comment doit-il faire ce travail ?
FormeMCP : un processus serveur JSON-RPC.
Skill : un dossier de Markdown et de scripts.
Coût en contexteMCP : schémas de tous les outils chargés (sauf chargement différé).
Skill : quelques tokens, le reste à la demande.
ExempleMCP : lire Jira, requêter Postgres.
Skill : appliquer la charte d'équipe à un rapport.

Les deux se combinent : une Skill peut expliquer comment bien utiliser les outils d'un serveur MCP.

!Sécurité : on vous posera la question
  • Tool poisoning : une description d'outil malveillante cache des instructions. N'installez que des serveurs de confiance.
  • Trifecta létale : données privées + contenu non fiable + capacité à communiquer vers l'extérieur = exfiltration possible. Coupez au moins un des trois.
  • Moindre privilège : tokens à portée réduite, lecture seule par défaut, confirmation humaine pour les écritures.

Module 3 · 10 minJeux de tests · LLM-as-a-judge · traces

Sans évaluation, chaque changement de prompt est un pari.

La démarche qui marche : regarder les traces, nommer les modes d'échec, transformer chaque échec en cas de test, puis mesurer à chaque modification. On ne commence pas par une métrique générique : on commence par lire 50 conversations.

La boucle d'amélioration

1Instrumenterchaque appel LLM, outil, retrieval → un span
2Analyser les erreursannoter des traces, regrouper les échecs par catégorie
3Construire le jeu de testcas réels + cas limites, versionné comme du code
4Évaluerdéterministe d'abord (JSON, regex, outil appelé), juge LLM pour le subjectif
5CI et prodhors ligne avant de déployer, en ligne sur un échantillon

Quoi évaluer

Résultat finalRéférence, juge LLM ou test exécutable. Ex. le ticket créé a le bon statut.
Trajectoire d'agentAppels d'outils lus dans la trace. Ex. search avant refund, moins de 8 étapes.
Retrieval (RAG)Recall@k, MRR, nDCG. Ex. le bon passage est dans le top 5.
Génération (RAG)Fidélité au contexte, pertinence (style RAGAS). Ex. chaque affirmation a une source.
OpérationnelLatence p95, coût par tâche, taux d'erreur d'outil.

LLM-as-a-judge, bien fait

Critère binaire« Cite-t-elle une source du contexte ? Oui/Non » plutôt qu'une note sur 10. Un juge par critère.
Raisonner, puis trancherJustification courte d'abord, verdict en JSON ensuite.
Calibrer contre l'humainUne centaine de cas annotés ; mesurer vrais positifs et vrais négatifs, pas seulement l'accuracy.
Biais connusPosition (préfère la 1re réponse : inversez l'ordre), verbosité (préfère le plus long), auto-préférence (favorise ses propres sorties).
Pointwise ou pairwiseA/B plus stable pour choisir entre deux versions ; pointwise pour le monitoring.

Traces et OpenTelemetry

Une trace = une requête de bout en bout. Elle contient des spans imbriqués (appel LLM, outil, retrieval) avec entrées, sorties, durée, tokens et coût. OpenTelemetry est le standard ouvert pour les produire ; ses conventions GenAI nomment les attributs (gen_ai.request.model, gen_ai.usage.input_tokens…). Instrumenter en OTel évite de dépendre d'un fournisseur.

Langfuse (open source, auto-hébergeable) reçoit ces traces et ajoute prompts versionnés, datasets, scores et évaluateurs LLM-as-a-judge. Alternatives : LangSmith, Arize Phoenix, Braintrust, Logfire.

!Regard critique
  • Un score moyen qui monte peut cacher une régression sur une catégorie : découpez par type de cas.
  • Les LLM ne sont pas déterministes : plusieurs essais, regardez la variance (pass@k, pass^k).
  • Un juge non calibré mesure surtout ses propres goûts.

Module 4 · 12 minEmbeddings · hybride · reranking · bases vectorielles

RAG : retrouver les bons passages, puis répondre avec.

La qualité d'un RAG se joue presque toujours au retrieval. Si le bon passage n'est pas dans le contexte, aucun modèle ne peut répondre juste. Mesurez le retrieval séparément de la génération.

Hors ligne · indexation
1Documents → chunkspassages de quelques centaines de tokens
2Embeddings + indexHNSW pour le dense, BM25 pour le lexical
En ligne · requête
Densetop 50 par sens
BM25top 50 par mots
fusion RRF
3Rerankingcross-encoder → top 5
4LLM + citationsrépond à partir des passages

Les briques

EEmbeddingstexte → vecteur

Un modèle transforme un texte en vecteur (souvent 384 à 3072 dimensions). Deux textes de sens proche donnent des vecteurs proches, mesurés par similarité cosinus. Même modèle pour documents et requêtes.

Exemples : OpenAI text-embedding-3, Voyage, Cohere ; en open-weight BGE-M3, Qwen3-Embedding. Comparez sur MTEB, puis sur vos données.

CChunkingdécouper sans perdre le sens

Quelques centaines de tokens, avec chevauchement, en respectant la structure (titres, paragraphes).

Le contextual retrieval ajoute à chaque chunk une phrase de contexte générée par un LLM (« Extrait du rapport Q2 d'ACME, section marges ») avant de l'indexer.

HRecherche hybridesens + mots exacts

Le dense capte le sens et les paraphrases. BM25 (lexical) capte les termes exacts : codes produit, noms propres, numéros d'erreur. On combine les deux classements.

RFusion RRFReciprocal Rank Fusion

score(d) = Σ 1 / (k + rang(d)) avec k = 60. N'utilise que les rangs : pas besoin de normaliser des scores incomparables. Essayez l'atelier ci-dessous.

XRerankingcross-encoder sur le top 50

Un cross-encoder lit la question et le passage ensemble et donne un score de pertinence. Plus précis qu'un bi-encoder (embeddings calculés séparément), mais trop lent pour tout le corpus. Exemples : Cohere Rerank, bge-reranker, ou un LLM.

∑Atelier · la fusion RRF

Deux moteurs classent les mêmes documents (1 = meilleur, vide = absent). « Erreur E-4012 » est 1er en BM25 grâce au code exact, mais 9e en dense. Modifiez les rangs.

Un k petit donne beaucoup de poids aux premiers rangs ; un k grand lisse les écarts.

Bases vectorielles

Comparer la requête à des millions de vecteurs un par un est trop lent : on utilise un index ANN (approximate nearest neighbors). HNSW est un graphe navigable à plusieurs niveaux, rapide et précis mais gourmand en mémoire. IVF regroupe les vecteurs en clusters et ne fouille que les plus proches. La quantization réduit la mémoire au prix d'un peu de précision.

pgvectorExtension Postgres. Vecteurs à côté des données métier : transactions, jointures, filtres SQL. Index HNSW ou IVFFlat. Hybride via tsvector + RRF en SQL. Le choix par défaut si vous avez déjà Postgres.
QdrantBase dédiée en Rust. Filtres sur payload rapides, vecteurs denses + sparses (hybride natif), quantization, multi-vecteurs. Pour gros volumes ou filtrage intensif.
AutresWeaviate, Milvus, Pinecone (managé), Chroma (prototypage), Elasticsearch/OpenSearch. Le choix dépend du volume, du filtrage et de l'exploitation, rarement de la vitesse brute.
pgvector · stocker et chercher 
CREATE EXTENSION vector;
CREATE TABLE chunks (
  id bigserial PRIMARY KEY,
  doc_id int, content text,
  embedding vector(1024));
CREATE INDEX ON chunks
  USING hnsw (embedding vector_cosine_ops);

SELECT id, content,
       1 - (embedding <=> $1) AS similarite
FROM chunks
WHERE doc_id = ANY($2)      -- filtre métier
ORDER BY embedding <=> $1 LIMIT 50;

-- <=> cosinus · <-> L2 · <#> produit scalaire négatif
!Pièges classiques
  • Chunks trop petits : sens perdu. Trop gros : signal dilué. Testez plusieurs tailles avec votre recall@k.
  • Changer de modèle d'embedding impose de tout réindexer.
  • Filtrer après la recherche ANN peut ne rien laisser : filtrez pendant la recherche.
  • Les questions multi-étapes (« compare X et Y ») demandent plusieurs recherches : donnez au modèle un outil de recherche et laissez-le itérer. C'est le RAG agentique.

Module 5 · 10 minLoRA · TRL · Unsloth · vLLM

Modèles open-weight : adapter, puis servir.

« Open-weight » veut dire que les poids sont téléchargeables, pas forcément les données ni le code d'entraînement, et la licence n'autorise pas toujours tout. Familles courantes : Llama, Qwen, Mistral, Gemma, DeepSeek, gpt-oss.

Faut-il fine-tuner ?

Dans l'ordre : prompt, puis exemples few-shot, puis RAG, et seulement ensuite fine-tuning. Le fine-tuning change un comportement : format de sortie, style, tâche étroite répétée, ou rendre un petit modèle aussi bon qu'un gros sur votre tâche. Il est mauvais pour ajouter des connaissances : pour ça, utilisez le RAG.

SFTSupervised fine-tuning : paires instruction → réponse idéale.
DPOPaires réponse préférée / rejetée, sans modèle de récompense séparé.
RL vérifiable (GRPO…)La récompense vient d'un test qui passe, d'un calcul juste, d'un format valide.

LoRA et QLoRA

Au lieu de modifier une matrice de poids W (d × k), on la gèle et on apprend une mise à jour de rang faible : W' = W + (α/r)·B·A, avec B (d × r), A (r × k) et r petit (8 à 64). On entraîne moins de 1 % des paramètres ; l'adaptateur pèse quelques Mo. QLoRA charge en plus le modèle de base en 4 bits (NF4) : un modèle de 8 milliards de paramètres se fine-tune sur un seul GPU grand public.

L'outillage

TRLHugging Face. Trainers prêts à l'emploi : SFTTrainer, DPOTrainer, GRPOTrainer. Fonctionne avec PEFT, qui fournit LoRA.
UnslothNoyaux de calcul réécrits : environ 2× plus rapide, beaucoup moins de VRAM. Compatible TRL, idéal pour QLoRA sur un seul GPU.
DonnéesQuelques centaines à milliers d'exemples propres valent mieux que beaucoup d'exemples bruités. Gardez un jeu d'éval séparé et comparez au modèle de base.

Le moteur d'inférence open source le plus répandu en production. Deux idées à connaître :

Module 6 · 6 minClaude Code · Cursor · Codex

Assistants de code : aller vite sans perdre le contrôle.

Ces outils sont eux-mêmes des agents : un LLM, des outils (lire, éditer, lancer des commandes) et une boucle. Tout ce qui précède s'applique. Votre valeur ajoutée, c'est le contexte que vous donnez et la relecture que vous faites.

Claude CodeAgent en terminal, IDE, web et desktop. CLAUDE.md, sous-agents, hooks, MCP, Skills, slash commands, mode plan.
CursorIDE dérivé de VS Code. Autocomplétion, mode agent, règles de projet, indexation du code.
CodexCLI, IDE et cloud (OpenAI). AGENTS.md, tâches parallèles dans le cloud, sandbox.
AutresGitHub Copilot, Windsurf, Gemini CLI, Aider… Même logique : contexte, outils, boucle.

Une pratique qui tient

Fichier de contexte courtCLAUDE.md / AGENTS.md : commandes de build et de test, conventions, ce qu'il ne faut pas toucher.
Plan d'abordDemander un plan avant le code sur toute tâche non triviale.
Petits pasTâches petites, diffs lisibles, un commit par étape.
Tests comme oracleÉcrire ou valider les tests d'abord, laisser l'agent les lancer.
Session neuveNouvelle tâche, nouvelle session : pas de contexte pollué.
!Ce qu'on relit toujours
  • APIs ou paquets inventés : vérifiez qu'ils existent. Des attaquants enregistrent les noms hallucinés (slopsquatting).
  • Tests trafiqués : assertions affaiblies, cas supprimés, mocks qui testent le mock.
  • Erreurs avalées : try/except: pass, valeurs par défaut silencieuses.
  • Sécurité : secrets en dur, injection SQL ou shell, validation absente.
  • Sur-ingénierie et doublons : abstractions inutiles, code existant réécrit à côté.
  • Assurance trompeuse : « c'est corrigé » sans que les tests aient tourné.

4RAGHybride dense + BM25, fusion RRF, reranking cross-encoder, pgvector par défaut, Qdrant à grande échelle. Mesurer le recall@k.

5ServingvLLM : PagedAttention + continuous batching, API compatible OpenAI, multi-LoRA. VRAM ≈ paramètres × octets + KV cache.
